# Провенанс в досье: происхождение данных вместо прозы

Дата: 3 сентября 2026. Статус: согласован, готов к плану реализации.

## Задача

Продуктовый принцип требует, чтобы интерфейс различал **наблюдение, вычисление,
прокси и отсутствие данных** (раздел «Доверие и ответственность» в описании
проекта). Четвёртое состояние работает: блок деградирует в `secondary` или
исчезает, синтетический ноль запрещён. Первые три не выражены ничем.

Сегодня происхождение данных в системе есть — но в двух местах, и оба
непригодны:

1. **Счётчиком.** `build_dossier` собирает множество `sources`
   (`route`, `communal`, `bars`, `crime`, `solar`, `noise`) и схлопывает его в
   `VerdictInfo.layers_checked = len(sources)`. Имена выбрасываются.
2. **Прозой.** `verdict_line` несёт происхождение текстом: «Оценка по модельным
   слоям: коммунальность — по году постройки, риск — по плотности
   алкомаркетов», «Свет рассчитан по геометрии зданий; шум — модель по типам
   дорог».

Проза не отрисовывается значком, не проверяется тестом и не переживает
экспорт. Пользователь не отличает измеренное от смоделированного, а
`urban_evidence.source` и `urban_evidence.observed_at` лежат в базе и не
выбираются даже запросом.

Работа состоит не в том, чтобы изобрести провенанс, а в том, чтобы **поднять
существующее знание до структуры**.

## Границы

**Входит:** блоки досье (`/dossier`, паспорт объекта), сквозной контракт на
трёх сторонах, отрисовка.

**Не входит:** карточки выдачи и карта — там провенанса нет и он не заявлен;
экспорт в PDF (отдельная работа, зависит от этой); наполнение данными
Санкт-Петербурга; замена заблокированного сборщика объявлений.

**Миграций БД нет.** Все нужные величины уже в таблицах.

## Контракт

### Python — `habitus/online/schema.py`

```python
SourceKind = Literal["observation", "computation", "proxy"]


class BlockSource(BaseModel):
    key: str                          # стабильный id: "noise", "solar", "communal"
    label: str                        # «Шум», «Инсоляция» — для человека
    kind: SourceKind
    basis: str                        # «модель по типам дорог»
    observed_at: date | None = None   # None — величина считается на месте
```

`LifestyleBlock` получает поле:

```python
sources: list[BlockSource] = []
```

Пустой список законен и означает «блок ничего не утверждает о происхождении», а
не «всё проверено». Это то же различие, что между «нет данных» и нулём.

### Go — `backend/internal/service/object_service.go`

`Block` получает `Sources []BlockSource \`json:"sources,omitempty"\``.

Go **не проксирует досье насквозь**: `decodeDossier` разбирает ответ ML в
типизированную структуру, и фронту уходит именно она. Поля, которого нет в
`Block`, фронт не увидит никогда. У `Block` есть собственный `UnmarshalJSON`
(он сужает `Data` по ключу блока) — новое поле нужно добавить и туда, иначе оно
потеряется молча.

### TypeScript — `frontend/lib/agent/types.ts`

```ts
export type SourceKind = "observation" | "computation" | "proxy";

export interface BlockSource {
  key: string;
  label: string;
  kind: SourceKind;
  basis: string;
  observed_at?: string | null;
}
```

`LifestyleBlock` получает `sources?: BlockSource[]`.

### Худший уровень не хранится

Порядок строгости — `proxy > computation > observation`. Худший уровень блока
**выводится из списка на месте использования и нигде не хранится**. Отдельное
поле рядом со списком — второй источник правды, который разъедется при первой
же правке карты источников.

## Карта источников

Содержательная часть работы: чем именно является каждая величина в досье.

| Блок | Источник | `kind` | `basis` | `observed_at` |
|---|---|---|---|---|
| `family_routing` | Дорожный граф | computation | маршрут по дорожному графу | нет — считается на месте |
| `family_routing` | Граф метро/МЦК/МЦД | computation | перегоны, пересадки и интервалы | `updated_at` таблиц `metro_*` |
| `social_environment` (hero) | Коммунальность | **proxy** | оценка по году постройки дома | `MAX(observed_at)` слоя `communal` |
| `social_environment` (hero) | Риск | **proxy** | оценка по плотности алкомаркетов | `MAX(observed_at)` слоя `crime` |
| `social_environment` | Заведения | observation | POI OpenStreetMap в радиусе 500 м | `updated_at` таблицы `poi` |
| `view_and_climate` | Инсоляция | computation | расчёт по геометрии зданий | `updated_at` таблицы `urban_features` |
| `view_and_climate` | Шум | **proxy** | модель по типам дорог | `MAX(observed_at)` слоя `noise` |
| `view_and_climate` | Облачность | observation | климатология NASA POWER | нет — многолетняя норма |
| `view_and_climate` | Сторона света | observation | указана продавцом в описании объявления | нет |
| `logistics` | Пешая доступность | computation | расчёт по POI | `updated_at` таблицы `poi` |

**Три прокси из десяти** — ровно то, что сегодня спрятано в прозе и невидимо
пользователю.

### Откуда берутся даты

- `MAX(observed_at)` — колонка `urban_evidence.observed_at`, `NOT NULL` по
  схеме. Запросы в `_social_data` и шумовой запрос в `_climate_data` её сейчас
  не выбирают; добавляется в те же запросы, без второго обращения к БД.
- Даты импорта — `updated_at` соответствующих таблиц. Колонка есть у всех
  перечисленных.
- Где даты нет по существу (маршрут считается на месте, климатическая норма не
  датирована) — `observed_at` остаётся `None`. **Подставлять `now()` запрещено**:
  это ровно тот синтетический ноль, который продукт не допускает в измерениях.

## Что уходит из `verdict_line`

`verdict_line` перестаёт нести происхождение — оно живёт только в `sources`.
Иначе у одного факта два представления, и они разъедутся.

| Блок | Было | Станет |
|---|---|---|
| `social_environment` | «Оценка по модельным слоям: коммунальность — по году постройки, риск — по плотности алкомаркетов» | «Оценка окружения в радиусе 500 м» |
| `view_and_climate` | «Свет рассчитан по геометрии зданий; шум — модель по типам дорог» | «Освещённость, вид и шумовой фон» |
| `family_routing` | «Маршруты построены по дорожному графу и графу метро/МЦК/МЦД» | «Маршруты построены по подтверждённым данным» |

Вердикт остаётся вердиктом, происхождение становится данными.

## Отрисовка

**Строка источников под каждым блоком.** Для каждого — уровень, `basis` и дата,
если она есть. Дата без значения не показывается вовсе; «дата неизвестна»
писать не нужно, отсутствие строки уже это и означает.

**Плашка на заголовке блока — только когда худший уровень `proxy`.**
«Вычисление» — нормальный режим работы продукта, и значок на нём обесценил бы
значок на прокси: если помечено всё, не помечено ничто. Пользователь должен
видеть выделенным именно то, чему стоит верить меньше.

**«Нет данных» не трогаем.** Оно уже выражается отсутствием блока или его
понижением в `secondary`. Дублировать его четвёртым значком незачем.

## Тесты

Пишутся до реализации, каждый сначала падает.

**Python (`pytest`):**
- прокси-слои помечены `proxy`, а не `computation` — по одному тесту на
  `communal`, `crime`, `noise`;
- `observed_at` вычисляемого источника — `None`, а не `now()`;
- блок, который что-то утверждает, имеет непустой `sources`;
- `observed_at` слоя равен `MAX(observed_at)` строк, попавших в радиус, а не
  дате запроса.

**Go:** контрактный тест рядом с `TestDecodeDossierNarrowsHeroDataByKey` — что
`sources` переживает `decodeDossier`. Единственный способ поймать регресс:
без него поле теряется молча, без ошибки.

**Frontend (`vitest`):**
- блок с источником `proxy` показывает плашку;
- блок только с `computation` и `observation` плашку не показывает;
- источник без `observed_at` рисуется без даты, а не с пустым местом под неё.

## Решения, принятые по ходу

1. **Провенанс — отдельное поле, а не запись в `metrics`.** `metrics` хранит
   измеренные величины блока; провенанс лёг бы туда строками без типа, и
   проверить его тестом было бы нечем.
2. **Сторона света — `observation` с `basis`, называющим информанта.** Величина
   извлекается языковой моделью из прозы объявления (`extract-windows`), то есть
   наблюдение сделал продавец, а не продукт. Словарь из трёх уровней описывает
   способ получения величины, а не доверие к информанту, поэтому информант
   назван в `basis` — «указана продавцом в описании объявления». Это осознанный
   компромисс: плашки такой источник не получит. Если он должен выделяться
   наравне с прокси, правило плашки нужно менять здесь же, до реализации.
3. **`layers_checked` остаётся.** Число проверенных слоёв — не то же самое, что
   их происхождение, и вычислять его из `sources` не требуется. Трогать
   `VerdictInfo` эта работа не будет.

## Риски

- **Карта источников — экспертное суждение, а не вывод из кода.** Ошибка в
  уровне опаснее его отсутствия: неверная пометка «наблюдение» на модельной
  величине создаёт ровно то ложное доверие, против которого работа затевалась.
  Карту нужно перечитать глазами до реализации — это дешевле, чем после.
- **Кэш досье переживает выкладку.** `chat_search_results.dossier` хранит сырой
  ответ ML под `schema_version = "dossier-v1"`. Старые записи не содержат
  `sources`; фронт обязан переживать их отсутствие (поле необязательное), а не
  падать. Версию схемы эта работа не поднимает: добавление необязательного поля
  контракт не ломает.
