# Map Viewport Optimization Implementation Plan

**Goal:** Сделать карту Habitus отзывчивой и предсказуемой: показывать и ранжировать квартиры только из видимой области, обновлять данные после движения карты и корректно центрировать результаты поиска.

**Approach:** Отделить геометрию видимой области от компонентов, обновлять viewport по событию `idle` с debounce, отменять устаревшие запросы через `AbortController`, фильтровать и ранжировать результаты на клиенте, а инфраструктурные данные загружать только для текущей области с небольшим буфером.

**Key tools/dependencies:** React, Zustand, Google Maps JavaScript API, `@googlemaps/markerclusterer`, `AbortController`, TypeScript.

---

## Task 1: Добавить чистые утилиты viewport и ранжирования

**Files:**
- Create: `frontend/lib/map/viewport.ts`

1. Добавить проверку попадания координат в viewport, включая переход через 180-й меридиан.
2. Добавить расширение viewport на 10% для фоновой загрузки инфраструктуры.
3. Добавить вычисление расстояния до центра карты.
4. Добавить стабильное ранжирование видимых квартир: сначала пятибалльная группа `match_score`, затем расстояние до центра, затем точный score и исходный порядок.
5. Проверить файл командой `npx tsc --noEmit` после интеграции со всеми потребителями.

## Task 2: Поддержать отмену сетевых запросов карты

**Files:**
- Modify: `frontend/lib/api/geo.ts`
- Modify: `frontend/lib/store/session.ts`

1. Передавать опциональный `AbortSignal` в запросы квартир и слоёв.
2. Добавить единый цикл обновления viewport: отмена прошлого запроса, параллельная загрузка квартир и активных слоёв, применение ответа только для последнего viewport.
3. Хранить признак `mapUpdating`, не очищая старые данные во время загрузки.
4. Перезагружать активные слои при каждом зафиксированном viewport; отключённые слои не запрашивать.
5. Один раз догружать полный пул результатов поиска (до серверного лимита 50), чтобы viewport-ранжирование работало не только по первой странице.

## Task 3: Обновлять карту после завершения движения

**Files:**
- Modify: `frontend/components/map/MapCanvas.tsx`
- Create: `frontend/components/map/MapUpdateIndicator.tsx`
- Modify: `frontend/app/globals.css`

1. На `dragstart` и изменении масштаба отмечать карту как движущуюся.
2. На `idle` запускать debounce 300 мс и только затем публиковать новый viewport.
3. Показывать неблокирующий spinner с подписью «Обновляю область» в правом верхнем углу карты во время загрузки.
4. Пока данные обновляются, снижать opacity маркеров квартир и инфраструктуры до 78%, не изменяя карту и её контролы.
5. Не добавлять общий оверлей: карта остаётся полностью интерактивной, а плашка и маркеры используют `pointer-events: none` или не перехватывают управление.
6. Создавать маркеры результатов только для квартир текущего viewport.
7. Показывать инфраструктурные точки только на подходящем масштабе; данные за пределами buffered viewport не держать в активном слое.

## Task 4: Исправить начальное центрирование результатов

**Files:**
- Modify: `frontend/components/map/MapCanvas.tsx`

1. Валидировать координаты зоны и квартир.
2. Центрировать карту по десяти лучшим результатам; использовать геометрию зоны только как fallback.
3. Ограничить чрезмерное приближение после `fitBounds`, чтобы одиночный результат не уводил пользователя с контекста района.
4. Не перецентрировать карту повторно после ручного движения пользователя.
