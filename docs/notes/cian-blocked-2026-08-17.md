# Сборщик заблокирован источником — 17 августа 2026

## Что случилось

Обход 17 августа собрал 2366 объявлений и получил капчу на 22-й странице
фильтра `room=3`:

```
22:32:14 cian-parser: room=3 page=22: Cian request failed after 4 attempts:
         Cian anti-bot returned a captcha or blocked response
exit status 1
```

Собранное не пропало — заливка прошла отдельным запуском, база выросла до
2720 активных объявлений, 99,96% с фотографиями.

## Почему заблокировали

Не из-за скорости. Парсер соблюдал случайную задержку 3–6 секунд (значение по
умолчанию в `cmd/cian-parser/main.go`) и подменял TLS-отпечаток под настоящий
Chrome со случайным выбором идентичности.

Арифметика обхода:

| | |
|---|---|
| Длительность | 22:23:27 → 22:32:14, ~9 минут |
| Страниц запрошено | ~85 (по 28 объявлений) |
| Темп | ~11 запросов в минуту |
| Источник | один домашний IP, прямое соединение, без прокси |

Сработала поведенческая проверка, а не проверка отпечатка: монотонная
пагинация по 22 страницы на четырёх фильтрах, ни одного перехода внутрь
объявления, ровные интервалы, один адрес. Плюс накопленная репутация IP —
с него же ходили 15 августа (1500 объявлений).

Режим прямого подключения изначально задумывался как временный: парсер сам
предупреждает при старте, что для него Циан обычно отдаёт капчу.

## Два пути

**Прокси.** То, подо что система спроектирована: `CIAN_PROXIES` в конфиге,
пул с ротацией в `internal/cian/pool.go`, закомментированная строка
`HABITUS_PROXY_FILE` в `scripts/com.habitus.refresh.plist`. Стоит денег,
но это единственный способ ходить регулярно и помногу.

**Ходить меньше и чаще.** Сейчас `HABITUS_MAX_OFFERS=5000` за обход — отсюда
85 страниц подряд. При 300–500 за цикл обход занимает 5–8 страниц, что похоже
на человека, смотрящего первые страницы выдачи. Четыре цикла в сутки дают те
же ~1500 объявлений в день, но размазанными. Окно гашения в два обхода
(`CRAWLS_KEPT` в `habitus/update/incremental.py`) такой режим переживает.

Второй вариант ничего не стоит и делается правкой одной переменной в
`scripts/refresh.sh`. Решение по первому — за владельцем проекта.

## Что проверить при возврате к теме

- Снялась ли блокировка: планировщик пробует каждые 6 часов, смотреть
  `data/refresh.log` на строку «сбор объявлений» без ошибки.
- Сколько объявлений из 571 погашенного вернётся в продажу после следующего
  полного обхода (загрузчик оживляет их сам через `is_active=true`
  в `ON CONFLICT`).
