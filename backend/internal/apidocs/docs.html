Подбор жилья по запросу словами

Habitus читает то, как человек описывает свою жизнь, и возвращает квартиры, объясняя каждую фактами о районе: сколько ребёнку идти до школы, куда выходят окна, что вокруг по вечерам.

Partner API отдаёт то же ядро, что работает в самом продукте. Вы получаете поиск, разбор запроса, досье объекта, слои города, свою витрину и заявки покупателей.

Человек говорит
Двушка до 18 миллионов, чтобы ребёнку пешком до школы и окна не на трассу
API возвращает разбор
"parsed": {
  "price_max": 18000000,
  "rooms": [2],
  "geo": [{ "kind": "school", "walk_minutes": 15 }],
  "noise_max": "moderate",
  "window_orientation": [],   // не сказано — не выдумано
  "semantic_text": "тихая квартира для семьи с ребёнком"
}

База: https://api.habitus.city. Локально после docker compose up — http://localhost:8080. Все ручки живут под /partner/v1, отвечают JSON в UTF-8 и требуют ключ, кроме /status и /openapi.json.

Первый запрос

Три шага от ключа до выдачи. Дальше всё строится вокруг идентификатора поиска: по нему запрашивают следующие страницы, досье объекта и ответы на вопросы.

1. Проверьте ключ

GET /partner/v1/me отвечает сразу на три вопроса: рабочий ли ключ, что им разрешено и в какие лимиты вы упрётесь.

2. Найдите квартиры

POST /partner/v1/search — синхронный запрос без стриминга. Разбор, подбор и пересчёт совпадения занимают от нескольких секунд до минуты, поэтому держите таймаут клиента не меньше 120 секунд.

3. Откройте досье

Карточка объекта в контексте поиска приходит с процентом совпадения, вердиктом и блоками разбора — маршруты семьи, социальная среда, вид и инсоляция.

Досье считается лениво при первом обращении и кэшируется. Первый вызов по объекту заметно дольше следующих — это нормально.

Как получить доступ

Самостоятельной регистрации нет. Ключи выдаются вручную, после согласования — и это не временное ограничение, а решение: ручка «создай себе ключ» — это ручка «создай себе доступ».

  1. Напишите нам на api@habitus.city. Понадобятся название компании, что вы собираетесь делать, и адреса, с которых будут уходить запросы.
  2. Мы заводим партнёра. Он появляется в состоянии «ожидает» — доступа у него ещё нет.
  3. Кто-то у нас одобряет доступ. Отдельным действием, с указанием основания. Это событие записывается вместе с именем того, кто его совершил.
  4. Выпускается ключ — с минимальным набором прав под вашу задачу, сроком действия и, если вы назвали адреса, списком сетей.

Ключ показывается один раз, в момент выпуска. В системе хранится не он, а его отпечаток — восстановить ключ не можем ни мы, ни вы. Потеряли — выпускаем новый, старый отзываем.

Срок действия

Ключ действует 180 дней, если не договорились иначе. Дата видна в expires_at ответа /me — поставьте напоминание за пару недель и попросите новый заранее. Бессрочные ключи выпускаются в виде исключения: ключ, утёкший год назад, работает ровно до того дня, когда кто-то заметит счёт за трафик.

Адреса

Если вы назвали адреса или подсети, ключ работает только оттуда. Запрос с любого другого адреса получит 403 ip_not_allowed — это не проблема прав, это несовпадение сети. Список видно в allowed_ips ответа /me; пустой означает «откуда угодно».

Меняете хостинг или добавляете новый регион — предупредите заранее. Иначе интеграция встанет в момент переезда, и выглядеть это будет как отказ прав.

Что делать при утечке

Напишите нам сразу — отзыв занимает минуту, и отозванный ключ перестаёт работать немедленно. Не ждите подтверждения утечки: выпустить новый ключ дешевле, чем разбираться, кто выкачал базу.

Ключи и права

Ключ передаётся заголовком Authorization: Bearer hab_live_…. Cookie здесь не используются: у интеграции нет браузера.

Секрет показывается один раз — в момент выпуска. В системе хранится только его хеш, поэтому потерянный ключ нельзя восстановить, можно лишь выпустить новый и отозвать старый.

Среды

Префикс ключа говорит, в какой среде он работает: hab_live_… — боевые данные, hab_test_… — тот же контур с пометкой, по которой вы отличаете свои прогоны от продакшена. Среда видна в ответе /me.

Права

Каждый ключ несёт набор прав. Ключ для CRM не должен уметь читать слои города, а ключ витрины — чужие заявки: выдавайте ровно то, что нужно интеграции.

ПравоЧто открывает

geo:readСлои города и объявления под вьюпортом
listings:readЧтение своей витрины
listings:writeСоздание, изменение, публикация объявлений
leads:readЗаявки покупателей по вашим объявлениям

Форма ответов

Каждый ресурс несёт поле object с именем своего типа — search, search_result, property, listing, lead, webhook. Разбирайте ответ по нему, а не по тому, из какой ручки он приехал: так код переживёт добавление новых полей и вложений.

Координаты

Везде пара [lng, lat] в WGS84 (EPSG:4326) — сначала долгота. Никаких преобразований на вашей стороне не требуется. Перепутанный порядок — самая частая ошибка интеграции, поэтому при записи объявления координаты за пределами допустимого диапазона отклоняются с объяснением, а не принимаются молча.

Время

Все метки времени — RFC 3339 в UTC: 2026-09-06T09:14:22Z.

Деньги и площади

Цена — целое число рублей. Площадь — число с плавающей точкой в квадратных метрах. Ни то, ни другое не форматируется на нашей стороне.

Чего здесь не бывает

Главное правило сервиса: не выдумывать факты о городе. Оно определяет форму ответов сильнее, чем что-либо ещё, и нарушает привычное ожидание «в JSON всегда есть все поля».

  • Отсутствующий замер приходит как null, а не как ноль. Ноль минут до школы — это утверждение, что школа во дворе. Если данных нет, поле придёт пустым, и подставлять вместо него ноль на своей стороне тоже не стоит.
  • Блок досье, под который не хватило данных, деградирует или исчезает. Не рассчитывайте на фиксированный набор блоков: перебирайте blocks по key.
  • Названия объектов синтезированы из структурных фактов — «2-комнатная, 54 м²». Рекламных заголовков в API нет.
  • Процент совпадения существует только внутри запроса. Вне поиска он равен нулю и означает «не считался», а не «плохо подходит».

Откуда взялась величина

Каждый блок досье перечисляет источники своих чисел в поле sources. Это не украшение: разница между замером и модельной оценкой определяет, можно ли показывать величину клиенту как факт.

ВидЧто означает
observationЗамер или запись в источнике данных.
computationРасчёт по данным: маршрут по графу улиц, площадь буфера.
proxyМодельная оценка. Показывать как измеренный факт нельзя.

Слои communal, noise и crime целиком относятся к третьему виду — это модели, а не датчики в каждом дворе.

Постраничность

Списки приходят в одном конверте: object: "list", массив data, счётчик total, флаг has_more и next_cursor.

Курсор непрозрачен — собирать его самостоятельно не нужно и нельзя. Листайте, пока has_more не станет false. Неверный курсор возвращает 400, а не первую страницу: молчаливый сброс закольцевал бы вас на первой странице навсегда.

Размер страницы задаётся параметром limit — до 100, по умолчанию 25.

Выдача поиска уже сохранена целиком, поэтому листание страниц не запускает поиск заново и не тратит квоту на модель.

  "total": 28,
  "has_more": true,

def all_results(search_id):
    cursor = None
    while True:
        params = {"limit": 50}
        if cursor:
            params["cursor"] = cursor
        page = api.get(f"/searches/{search_id}/results", params=params).json()
        yield from page["data"]
        if not page["has_more"]:
            return
        cursor = page["next_cursor"]
async function* allResults(searchId) {
  let cursor = null;
  for (;;) {
    const qs = new URLSearchParams({ limit: "50" });
    if (cursor) qs.set("cursor", cursor);
    const page = await api(`/searches/${searchId}/results?${qs}`);
    yield* page.data;
    if (!page.has_more) return;
    cursor = page.next_cursor;
  }
}

Лимиты

Лимитов два, и они считаются раздельно. Тысяча дешёвых чтений в час — норма; тысяча вызовов модели — счёт за месяц.

КвотаОкноЧто попадает
ОбщаяСкользящая минутаВсе ручки
МодельСкользящий час/search, досье объекта, вопрос по объекту

Ваши значения видны в /me и приходят заголовками на каждом ответе — не только при отказе. Клиент должен уметь притормозить сам, а не узнавать о лимите в момент, когда в него уже упёрся.

ЗаголовокЗначение
RateLimit-LimitПотолок в текущем окне
RateLimit-RemainingСколько осталось
RateLimit-ResetЧерез сколько секунд освободится место
Retry-AfterТолько при 429 — сколько ждать

Те же значения дублируются как X-RateLimit-* — их понимают готовые клиенты.

При 429 повторяйте с растущей паузой, начиная со значения Retry-After. Повтор без паузы просто съедает следующее окно.

Повторные запросы

Сеть рвётся тогда, когда операция уже выполнена, но ответ до вас не дошёл. Чтобы повтор не создал второй объект, передайте заголовок Idempotency-Key с любой уникальной строкой до 255 символов.

  • Тот же ключ, то же тело — вернётся первый ответ с заголовком Idempotent-Replay: true. Вторая операция не выполняется.
  • Тот же ключ, другое тело — 409 idempotency_key_reuse. Отдать вам чужой сохранённый ответ было бы хуже отказа.
  • Неуспешный ответ не запоминается. Ошибку можно и нужно повторять тем же ключом — иначе клиент оказался бы заперт в ней навсегда.

Ключи хранятся 24 часа. Поддерживают его POST /search, POST /listings, POST /webhooks и вопрос по объекту.

Поиск

POST/partner/v1/searchsearch:read

Разбирает запрос, подбирает объекты и сохраняет выдачу. Возвращает поиск вместе с первой страницей.

ПолеОписание
query обяз.Запрос словами, до 2000 символов.

Что вернётся кроме объектов

parsed — что система поняла из запроса. relaxed — требования, которые пришлось ослабить, чтобы выдача не оказалась пустой; покажите их пользователю, иначе он не поймёт, почему в списке дороже, чем он просил. degraded — слои данных, недоступные в момент запроса. notes — примечания о покрытии: например, ориентация окон известна у малой доли объявлений, поэтому учитывается как предпочтение, а не как фильтр.

Объекты

GET/partner/v1/searches/{search_id}/properties/{object_id}search:read

Объект в контексте запроса: процент совпадения, вердикт и блоки досье. Первый вызов по объекту считает досье и потому дольше следующих.

Если объекта в этой выдаче не было, вернётся тот же объект без досье — это не ошибка. Так работает переход по прямой ссылке.

Вопрос по объекту

POST/partner/v1/searches/{search_id}/properties/{object_id}/asksearch:read

Ответ строится только по досье и фактам объекта. Чего в них нет — того не будет и в ответе.

Ответ приходит разложенным на предложения со ссылками на источники. Предложение с unknown: true означает «данных для ответа нет» — отдельным полем, чтобы вы могли отличить ответ от признания незнания программно, а не разбором текста.

Объект вне подбора

GET/partner/v1/properties/{object_id}search:read

Факты объекта без привязки к запросу: адрес, цена, площадь, этаж, фотографии, координаты и блоки, собранные из данных самого объекта.

Процента совпадения и досье здесь нет и быть не может: оба считаются относительно запроса. В отрыве от него это были бы выдуманные числа, а match_score придёт нулём — читайте это как «не считался».

СтатусЧто значит

СобытиеКогда приходит

Проверка подписи

Каждая доставка несёт заголовок X-Habitus-Signature вида t=<unix>,v1=<hex>. Подписывается строка <t>.<тело запроса как есть> алгоритмом HMAC-SHA256 на секрете подписки.

  • Считайте подпись от сырого тела, до разбора JSON: пересобранный JSON даст другие байты и другую подпись.
  • Сравнивайте постоянным по времени сравнением.
  • Отвергайте метки времени старше пяти минут — иначе перехваченный запрос можно повторять бесконечно.

Отвечайте любым кодом 2xx и как можно быстрее: тяжёлую работу ставьте в свою очередь. Долгий ответ считается неудачей и приводит к повтору.

Повторы и журнал

Неудачная доставка повторяется пять раз с растущей паузой — через минуту, пять минут, полчаса, два часа и шесть часов. Этого хватает пережить ночной деплой вашей CRM и мало, чтобы неделю долбиться в мёртвый адрес.

import hashlib, hmac, time

def verify(raw_body: bytes, header: str, secret: str) -> bool:
    parts = dict(p.split("=", 1) for p in header.split(","))
    ts, given = parts["t"], parts["v1"]

    # Старую метку не принимаем: иначе перехваченный запрос
    # можно повторять бесконечно.
    if abs(time.time() - int(ts)) > 300:
        return False

    expected = hmac.new(
        secret.encode(), f"{ts}.".encode() + raw_body, hashlib.sha256
    ).hexdigest()
    return hmac.compare_digest(expected, given)
import { createHmac, timingSafeEqual } from "node:crypto";

export function verify(rawBody, header, secret) {
  const parts = Object.fromEntries(
    header.split(",").map((p) => p.split("=")),
  );
  if (Math.abs(Date.now() / 1000 - Number(parts.t)) > 300) return false;

  const expected = createHmac("sha256", secret)
    .update(`${parts.t}.`)
    .update(rawBody)
    .digest();

  const given = Buffer.from(parts.v1, "hex");
  return expected.length === given.length && timingSafeEqual(expected, given);
}
func Verify(rawBody []byte, header, secret string) bool {
    var ts, given string
    for _, part := range strings.Split(header, ",") {
        k, v, _ := strings.Cut(part, "=")
        switch k {
        case "t":
            ts = v
        case "v1":
            given = v
        }
    }
    sec, err := strconv.ParseInt(ts, 10, 64)
    if err != nil || time.Since(time.Unix(sec, 0)) > 5*time.Minute {
        return false
    }

    mac := hmac.New(sha256.New, []byte(secret))
    fmt.Fprintf(mac, "%s.", ts)
    mac.Write(rawBody)
    return hmac.Equal([]byte(hex.EncodeToString(mac.Sum(nil))), []byte(given))
}

GET/partner/v1/openapi.jsonбез ключа

Спецификация OpenAPI 3.1. Вшита в сборку сервиса, поэтому не может разъехаться с тем, что реально задеплоено. Импортируйте её в Postman, Insomnia или генератор клиента.

Версии и совместимость

Версия живёт в пути: /partner/v1. Ломающее изменение поедет как /partner/v2, а не правкой действующей версии — у вашей интеграции свой релизный цикл, и «обновиться вместе с нами» она не может.

Что мы считаем совместимым изменением

  • Новое поле в ответе или новое необязательное поле в запросе.
  • Новая ручка, новое значение в перечислении, новый код ошибки.
  • Изменение текста в message: ветвиться нужно по code.

Пишите клиент так, чтобы незнакомые поля и значения не роняли разбор. Дата в поле api_version ответа /me говорит, на каком срезе контракта работает сервис сейчас.
